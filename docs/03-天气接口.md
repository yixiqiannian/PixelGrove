# 天气接口说明

## 1. 服务提供方

**和风天气（QWeather）** —— https://www.qweather.com/

使用前需在 [控制台](https://console.qweather.com/) 注册并创建项目，获取：

- **API Host**（每个账号独立，形如 `xxxxxx.re.qweatherapi.com`）
- **API KEY**
- **LocationID**（城市 ID）

> 免费订阅有每日调用次数限制。本项目默认 20 分钟刷新一次，一天约 72 次，足够。

### 署名要求

和风天气要求在使用其数据的应用中进行署名。开发板为私人设备，界面未强制显示，
如果你要公开发布固件，请遵守其[服务条款](https://www.qweather.com/terms)。

---

## 2. 接口端点

| 用途 | 端点 |
|---|---|
| 实况天气 | `GET https://{host}/v7/weather/now?location={id}&key={key}&lang=en` |
| 三天预报 | `GET https://{host}/v7/weather/3d?location={id}&key={key}&lang=en` |
| 城市搜索 | `GET https://{host}/geo/v2/city/lookup?location={城市名}&key={key}` |

### 重要限制

- `/v7/weather/*` 的 `location` 参数**只接受 LocationID 或经纬度**，**不接受城市名**
  - `location=hangzhou` → **HTTP 400**
  - `location=101210101` → ✅
- `lang=en` 可让 `text` / `windDir` 返回英文（`Overcast` / `E`）；不传则返回中文

## 3. ⚠️ 必须自己解压 gzip

这是本项目最容易踩的坑（详见 [05-踩坑记录 §5](05-踩坑记录.md)）。

**现象**：和风天气**无条件**返回 `Content-Encoding: gzip`，即使请求头声明 `Accept-Encoding: identity` 也一样压缩。

```
HTTP/1.1 200 OK
Content-Type: application/json
Content-Encoding: gzip
Content-Length: 297
```

**后果**：`esp_http_client` 不解压，297 字节 gzip 二进制喂给 `cJSON_Parse()` 直接返回 NULL。

**解决**：固件里用 zlib 手动解压：

```c
#include "zlib.h"

static int gunzip_if_needed(char *buf, int len, size_t cap)
{
    if(len < 2 || (uint8_t)buf[0] != 0x1f || (uint8_t)buf[1] != 0x8b)
        return len;                       // 非 gzip，原样返回

    static char plain[4096];
    z_stream s = {0};
    s.next_in  = (Bytef *)buf;   s.avail_in  = len;
    s.next_out = (Bytef *)plain; s.avail_out = sizeof(plain);

    if(inflateInit2(&s, 15 + 32) != Z_OK) return -1;   // 15+32 = 自动识别 gzip/zlib 头
    int rc = inflate(&s, Z_FINISH);
    inflateEnd(&s);

    if(rc != Z_STREAM_END || s.avail_out == 0) return -1;
    int out = sizeof(plain) - s.avail_out;
    memcpy(buf, plain, out);
    return out;
}
```

两个请求点（`fetch_now()` / `fetch_daily()`）都要调用。

**实测**：297 B gzip → 448 B 明文。

## 4. 返回字段

### `/v7/weather/now`

```json
{
  "code": "200",
  "updateTime": "2026-11-17T15:20+08:00",
  "now": {
    "temp": "16",
    "feelsLike": "15",
    "icon": "104",
    "text": "阴",
    "wind360": "90",
    "windDir": "东风",
    "windScale": "2",
    "humidity": "75",
    "pressure": "1014",
    "vis": "10",
    "obsTime": "2026-11-17T15:15+08:00"
  }
}
```

### `/v7/weather/3d`

```json
{
  "code": "200",
  "daily": [
    {
      "fxDate": "2026-11-17",
      "tempMax": "19",
      "tempMin": "13",
      "iconDay": "104",
      "textDay": "阴",
      "sunrise": "06:25",
      "sunset": "17:02"
    }
  ]
}
```

### 固件用到的字段

| 字段 | 用途 | 缺失时 |
|---|---|---|
| `now.temp` | 主温度 | 显示占位符 |
| `now.icon` | 选图标 + 判断雨雪（决定特效） | 回退阴天图标 |
| `now.text` | 天气文字 | 空 |
| `now.humidity` / `pressure` / `vis` / `feelsLike` | 详情页 | 占位符 |
| `now.windDir` + `windScale` | 风力 | 占位符 |
| `daily[0].tempMax/tempMin` | 今日高低温 | 占位符 |
| `daily[0].sunrise/sunset` | **昼夜判断** | 兜底 6:00–18:00 |
| `daily[1..2]` | 未来两天 | 该行留空 |

## 5. 图标代码映射

和风天气 icon code → 固件的 6 种图标（`icon_kind()`）：

| code 范围 | 图标 | 说明 |
|---|---|---|
| 400–499 | 雪 | 各类雪 |
| 300–399 | 雨 | 各类雨 |
| 100, 150 | 晴 | 晴 / 晴（夜间） |
| 101–103, 151–153 | 多云 | 多云 / 少云 / 阴转晴 |
| 其余（含 104、500+） | 阴 | 阴、雾、霾等全部回退到这里 |

**未识别 code 一律回退**，不会崩溃。

## 6. 时区处理

**不要用设备时区**。ESP32 的 SNTP 同步的是 UTC，设备所在地不可知。

正确做法：

```c
#define WX_TZ_OFFSET_SEC (8 * 3600)   // 查询城市的 UTC 偏移

time_t t = data_obs_time_utc;          // 接口 obsTime 换算成 UTC
time_t local = t + WX_TZ_OFFSET_SEC;
struct tm lt;
gmtime_r(&local, &lt);                  // 用 gmtime 而不是 localtime
```

`gmtime_r` + 手动偏移 = 得到"该城市的当地时间"，与设备时区无关。

季节判定与昼夜判定都基于这个 `lt`。

## 7. 查询城市 LocationID

```bash
curl -s --compressed "https://{host}/geo/v2/city/lookup?location=hangzhou&key={key}" \
  | python -m json.tool
```

返回：

```json
{
  "code": "200",
  "location": [{
    "name": "杭州",
    "id": "101210101",
    "lat": "30.28746",
    "lon": "120.15358",
    "tz": "Asia/Shanghai",
    "utcOffset": "+08:00"
  }]
}
```

把 `id` 填进 `WX_LOCATION_ID`，`utcOffset` 换成秒填进 `WX_TZ_OFFSET_SEC`。

**常用城市**：

| 城市 | LocationID | UTC 偏移 |
|---|---|---|
| 杭州 | `101210101` | +08:00 |
| 北京 | `101010100` | +08:00 |
| 上海 | `101020100` | +08:00 |
| 深圳 | `101280601` | +08:00 |
