# 构建与烧录

## 1. 环境要求

| 组件 | 版本 / 说明 |
|---|---|
| Windows | PowerShell 7（`pwsh`），不要用 Windows PowerShell 5 |
| ESP-IDF | **6.1**（由 PlatformIO 管理，无需单独安装） |
| PlatformIO Core | `espressif32@7.1.3`、`framework-espidf@4.60100.0` |
| Python | 3.11+（素材生成脚本 + esptool） |
| LVGL | **9.4.0**（`vendor/lvgl-9.4.0`，168 MB，不在仓库内） |
| 网络 | 首次编译需联网拉取托管组件（cjson / zlib / st77916 等） |

### 目录约定

构建脚本默认使用 `F:\CABadgeBuild` 作为构建根目录（可用环境变量 `CABADGE_BUILD_ROOT` 覆盖）：

```
F:\CABadgeBuild\
├── platformio\idf61\        PlatformIO / ESP-IDF 工具链
│   └── .cache\components\   托管组件缓存（约 95 MB）
├── staging\                 每次编译的临时工程
└── temp\
```

## 2. 配置 API 密钥

```bash
cd firmware/ui
cp weather_config.h.example weather_config.h
```

编辑 `weather_config.h`：

```c
#define WX_API_HOST   "your-host.qweatherapi.com"   // 控制台 → 设置 → API Host
#define WX_API_KEY    "YOUR_API_KEY_HERE"           // 控制台 → 设置 → API KEY
#define WX_LOCATION_ID "101210101"                  // 杭州
#define WX_CITY_LABEL  "杭州"
#define WX_TZ_OFFSET_SEC (8 * 3600)                 // 该城市 UTC 偏移
```

> ⚠️ `weather_config.h` 在 `.gitignore` 里，不会提交。**不要**把它改成 `.example` 以外的名字提交。

## 3. 编译

```powershell
cd <项目根>
pwsh -File firmware/build.ps1
```

带代理（国内网络需要）：

```bash
export HTTP_PROXY=http://127.0.0.1:10808
export HTTPS_PROXY=http://127.0.0.1:10808
export IDF_COMPONENT_CHECK_NEW_VERSION=0     # 组件缓存完整时跳过联网校验，避免卡住
pwsh -File firmware/build.ps1
```

### 编译耗时

| 场景 | 耗时 |
|---|---|
| 首次 / 全新 staging | 25–35 分钟 |
| 只改 `ui/*.c`（素材不变） | 16–25 分钟 |
| 只改 `ui/weather.c` 逻辑 | 约 16 分钟 |

### 成功标志

```
RAM:   [=         ]  15.0% (used 49056 bytes from 327680 bytes)
Flash: [========= ]  91.5% (used 6714099 bytes from 7340032 bytes)
========================= [SUCCESS] Took 1483.42 seconds =========================
```

产物在 `outputs/builds/<checkoutId>/cabadge-<version>-<timestamp>-<buildId>/`：
`bootloader.bin`、`partitions.bin`、`firmware.bin`

### Flash 超过 100% 怎么办

应用分区硬上限 **7 MB**。超了必须删内容，常见取舍：

| 删什么 | 省多少 |
|---|---|
| 开屏名片页（f56 字模 + logo） | 922 KiB |
| 阴天独立背景图 | 253 KiB |
| 雨雪特效 4 帧 → 2 帧 | 506 KiB |
| 树木 128×192 → 64×96 | 约 400 KiB |
| 移除一个应用（Grok / FluidBox） | 60–100 KiB |

## 4. 烧录

```bash
cd outputs/builds/<...>/cabadge-<...>/

python -m esptool --chip esp32s3 --port COM6 --baud 460800 \
  --before default_reset --after hard_reset write-flash \
  0x0 bootloader.bin \
  0x8000 partitions.bin \
  0x10000 firmware.bin
```

### 成功标志

```
Wrote 6973168 bytes (2355344 compressed) at 0x00010000 in 56.8 seconds
Verifying written data...
Hash of data verified.
Hard resetting via RTS pin...
```

### 串口说明

| 端口 | 用途 |
|---|---|
| `COM6` | 本板 USB-CDC（正常烧录口） |
| `COM3` | Intel AMT（**不要动**） |
| `COM4/COM5` | 蓝牙虚拟串口 |

> 设备没有普通 UART 日志输出，调试主要靠屏幕显示。天气应用的失败原因会直接上屏。

## 5. 回滚到旧固件

旧产物保留在 `outputs/builds/<checkoutId>/<旧版本目录>/`，直接烧回去：

```bash
cd outputs/builds/<old-checkout>/<old-version>/
python -m esptool --chip esp32s3 --port COM6 --baud 460800 \
  --before default_reset --after hard_reset write-flash \
  0x0 bootloader.bin 0x8000 partitions.bin 0x10000 firmware.bin
```

> **不要**只烧 `firmware.bin` 而跳过 bootloader/partitions——分区表不一致会启动失败。

## 6. 常见编译错误

| 错误 | 根因 | 解决 |
|---|---|---|
| `Failed to resolve component 'json'` | ESP-IDF 6.1 无内置 json | `REQUIRES` 改用 `espressif__cjson` |
| `Failed to resolve component 'zlib'` | 同上 | 改用 `espressif__zlib` |
| `error: unsigned conversion from 'int' to 'unsigned int:20'` | 字体 bitmap 偏移超 1 MiB | 缩小字号池或删大字号（见 05-踩坑记录 §2） |
| `Cannot establish a connection to the component registry` | 网络抖动 | 重试，或设 `IDF_COMPONENT_CHECK_NEW_VERSION=0` |
| 卡在 `Reading CMake configuration...` | CMake 配置慢 或 日志缓冲 | 查 staging 文件数是否增长，**不要急着杀进程** |
| `fatal error: ui/xxx.h: No such file` | `build.ps1` 复制列表漏了文件 | 补进 `build.ps1` 第 49 行附近的显式列表 |
| `undefined reference to 'lodepng_malloc'` | `app_service.c` 里的 PSRAM 分配函数被误删 | 原样补回三个 `lodepng_*` 函数 |

### build.ps1 的复制列表是显式的

`ui/` 根目录的文件**不是** glob 复制，是一个写死的文件名列表：

```powershell
foreach ($name in 'ui_transition_cache.c', ..., 'weather.c','weather.h',
                  'weather_config.h','weather_assets.c') { ... }
```

新增 `ui/` 下的文件必须手动加进这个列表，否则编译时报找不到头文件。

## 7. 素材变更后的重新生成流程

改了素材或中文文案后：

```bash
cd firmware

# 1. 字模（改了中文文案才需要）
python tools/generate_assets.py

# 2. 天气素材（改了背景/树/图标/雨雪才需要）
python tools/generate_weather_assets.py

# 3. 农场素材
python tools/generate_pixel_farm_assets.py
```

脚本从素材源目录读取 PNG，输出 `ui/*_assets.c`。

**素材源路径**写在脚本顶部的常量里，换机器需要改：

```python
ASSETS  = Path(r"F:\CABadgeBuild\pixel_farm_weather_assets_v1\pixel_farm_weather_v1")
SEASONS = Path(r"F:\CABadgeBuild\pixel_weather_seasons_addon_v1\pixel_weather_seasons_addon_v1")
NIGHTS  = Path(r"F:\CABadgeBuild\pixel_weather_four_seasons_night_v1 (1)\pixel_weather_four_seasons_night_v1")
```

素材已经全部整理进本仓库的 `assets/` 目录，可以改成指向那里。
